## Acceptance

- New pure `src/layout/rings.js`, chosen by strategy in `src/layout/canonical.js`: a named
  single carbocycle (3–30 C, bare/substituted/unsaturated) is a regular polygon, standard bond
  length, **locant 1 at the top vertex, numbering clockwise on screen** (from the naming
  result's ring order) — met (`tests/unit/ring-layout.test.js`: sizes 3–30, regularity,
  convention, determinism, id/order/coordinate invariance).
- Side chains leave along the exterior bisector (two on one atom: ± a sixth of the free
  angle), then the shared zigzag/collision search; clearance ≥ 0.5 bond lengths, no crossings,
  no side-chain atom or bond inside the ring; else the drawing stays and the existing message
  shows — met (seeded random test ≥ 500 rings, 0 failures).
- UI (`src/ui/results.js`): hint "¿Quieres ver el anillo ordenado?"; "Todavía no sé ordenar…"
  refusal removed; ring (closure included) highlighted; locants from "Numera el anillo" on,
  none for bare rings; one undo step, no step when already ordered — met (e2e
  `tests/e2e/rings.spec.js`, both projects).
- Benzene and non-nameable molecules keep their naming error; the 90° view keeps its ring
  fallback — met.

## Decisions / deviations

- "Ordenar dibujo disabled in the 90° view" applies while a 90° drawing is shown (design §7);
  a ring never gets one, so with the toggle on a ring shows the normal drawing and the button
  works.
- Tests that asserted the old ring refusal now assert a layout (`layout`, `rings`,
  `cycloalkanes`, `substituted-rings` unit tests; the e2e "Ordenar dibujo refuses it" test).
- `monocycleOrder` exported from `src/model/graph.js` for `layoutProblems()` (`drawnRing()`,
  new `inside` count).
