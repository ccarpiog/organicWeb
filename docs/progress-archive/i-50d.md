## What was built

- `src/reverse/diagnose.js`: five ring rule codes that take the place of chain rules 1–4 when the
  app's parent is the ring — `RING_IS_PARENT` (rule 1: `1-(4-metilfenil)propano`,
  `1-ciclohexilhexano`; «Ver el paso» at «Reconoce el benceno» / «Busca el anillo»), `BENZENE_RING`
  (rule 2: `ciclohexa-1,3,5-trieno`, benzene written with `ciclo`), `SUBSTITUTED_TEMPLATE` (rule 2:
  `4-metiltolueno`, `p-metiltolueno`, `4-metil-1,2-xileno`), `RING_NUMBERING` (rule 4:
  `1,5-dimetilciclohexano`, `1,5-dimetilbenceno`; reuses the chain numbering machinery),
  `LETTER_LOCANTS` (rule 11: `p-di(propan-2-il)benceno`, only when writing the letter as numbers
  gives the app's name). Chain rules 5–11 also run on rings; needless locants use the ring omission
  rules (`1-metilciclohexano`, `1-metilbenceno`, `ciclohex-1-eno`, `1,2,3,4,5,6-hexametilbenceno`).
  Ring codes share rule numbers with chain codes (1, 2, 4, 11); the code-table assertions in
  `reverse-diagnose.test.js` follow.
- `src/ui/draw-name.js`: ring legend labels «Cadena principal (el anillo)», «Tu anillo», «Tu anillo
  (es el mismo)».
- `src/reverse/index.js`: comment only. `CLAUDE.md`: v4 sentence (R-4d done, next R-5a).
- Tests: new `tests/unit/reverse-diagnose-rings.test.js` (one test per rule plus near-misses; a
  fixture sweep over 108 ring names and a generated-ring sweep over 554 names / 3 000+ `otherName`
  mutations: every `otherName` gets a diagnosis or a documented null, every step id resolves);
  four unit and three e2e specs that asserted «no ring diagnosis yet» now expect one.

## Decisions

- Deliberate, tested nulls: a ring branch whose own numbering is wrong always gets
  `RING_IS_PARENT` first (in a hydrocarbon the ring is always the parent); the reverse case (ring
  parent where the app picks a chain) cannot occur for hydrocarbons (tested); missing ring locants
  alone give `missingLocants` / `ambiguous`, never `otherName`; a chain branch of the ring with its
  own numbering wrong or in a style the app does not offer → null (`(butan-3-il)ciclohexano`,
  `(1,1-dimetiletil)benceno`, `p-di(butan-3-il)benceno`).
- **Affects chains too:** with left-out locants, a reading on which no rule finds a mistake makes
  the whole diagnosis null (before, another reading could be blamed for a numbering the student
  never wrote, e.g. `(butan-3-il)ciclohexano`). No chain test changed.
- Ayuda unchanged: «Del nombre al dibujo» does not list which mistakes are explained.

## Review (Codex, `docs/reviews/I-50d.md`) — ship-with-fixes, both fixed

- **BLOCKER** (`diagnose.js` rule 4): `1-etil-2-(1-metilpropil)benceno` was blamed for its ring
  numbering by a trace whose alphabetical tie-break used another prefix style (`butan-2-il`). Fix:
  the numbering rule may blame the N4/N5 alphabetical steps only if they used the citation order
  of the student's own words; otherwise it blames nothing and later rules still run → null here
  (as I-49a for an unoffered style). Same flaw in chain rule 4 (`5-etil-7-(1-metilpropil)undecano`,
  now null) and, extended beyond the review, rule 3 (chain choice at N4/N5:
  `5-(1-metilpropil)-6-(but-1-en-2-il)-7-metil-3-metilidennon-4-eno` now `ALPHABETICAL_ORDER`, not
  `CHAIN_LOCANTS`). Regressions assert the explanation cites prefixes in the student's order
  (`2-metil-1-(propan-2-il)benceno`, `1-metil-2-etilbenceno`, `4-etil-3-metilhexano`,
  `6-metil-4-(propan-2-il)nonano`). No sweep case changed; a 1 261-name sweep never fired the check
  on the app's own wording. Cautious side effect: `2-etil-1-(1-metilpropil)benceno` (unoffered style
  and wrong numbering) → null.
- **SHOULD-FIX** (`NEEDLESS_LOCANTS`): `1-(butan-2-il)benceno` told the student to write no numbers
  at all. Now, when the app's name keeps digits inside a branch, the message says only the number
  placing the substituent on the ring is left out and the branch's numbers stay; `metilbenceno`
  keeps the old text. The chain analogue cannot occur for hydrocarbons (rule 1 first; tested).
