## What was built

- **Tiles:** «Grupos» gains `hidroxi` (kind `hydroxy`, value 'alcohol', text from `GROUP_PREFIXES`) and `ol` (kind
  `suffix`, value 'alcohol', text from `GROUP_SUFFIXES`); «Anillos» gains `fenol` (kind `benzene`, value 'phenol', text
  `PHENOL_STEM` + `ol`) after `benceno`, and `1(n)` (kind `closing`) after the letters. `isAtomGroup()` names the
  one-atom prefixes (halogens and `hidroxi`), which share every code path of R-5a1.
- **Grammar:** `parent = [legacy] stem (ano | segments) [suffix] | [legacy] benceno [suffix] | fenol | …`,
  `suffix = [locants] [MULT] ol`, `locant = NUM | 1(n)`. The suffix node sits in `parent.suffix`; old-style locants go
  to the one list left open among segments and suffix (`2-propanol`, `1,2-etanodiol`, `1,2-bencenodiol`;
  `parent.legacySuffix`). Errors reuse the existing codes: TILE_ORDER (`ol` out of place, `bis` before `ol`, `fenol` in a
  branch, a multiplier before `fenol`, `1(n)` off a ring segment), LOCANT_COUNT, LEGACY (`2-butenol`: two open lists),
  TEMPLATE_LOCANTS (numbers or a letter before `fenol`), POSITIONAL (the OH of `fenol` and a benzene suffix's groups
  count as occupied positions: `o-dimetilfenol` is three).
- **Assembler (rule 4, suffix half):** the suffix multiplier loses its `a` before `ol` (`tetrol`, `pentol`, `hexol`),
  then the parent's last ending — `ano`, the last `eno`/`ino`, or `benceno` — loses its `o` when the multiplier + `ol`
  starts with a vowel (`propan-2-ol`, `prop-2-en-1-ol`, `bencenol`; kept in `butano-1,4-diol`, `butano-1,2,3,4-tetrol`,
  `bencenohexol`), as render.js `suffixWords()`/`renderEnding()`. `1(n)` is written with the ring's size (`1(6)`), a
  locant for the punctuation (`ciclopropa-1,1(3),2-trieno`).
- **Tokenizer:** new classes and the elided surfaces `tetr`… (only before `ol`) and `bencen` (before `ol` or its
  locants); `1(<digits>)` read as the `1(n)` tile wherever a ring bond locant may stand (the assembly checks the size).
- **Interpreter / builder:** NameSpec `suffix` = SuffixSpec `{kind, slots, multiplier, word, phenol, tiles}`, its slots
  role `carbon` on the parent (domain 1…n); `fenol` = benzene parent + one implicit slot at 1 on its tile; `1(n)` = a
  supplied ring-bond slot of value n with `closing` n; `hidroxi` = SubstituentSpec kind `hydroxy`, element O. Build adds
  one O per suffix group (single bond, after the parent, before the prefixes), lists them in `suffixAtoms`, counts them
  for the 80-heavy-atom cap, checks their range (LOCANT_RANGE), and marks `fenol`'s carbon 1 as the ring's own («…en el
  fenol, ese carbono ya lleva un grupo OH», like a template's group).
- **Search:** the suffix slots are one multiset group on the parent, each OH adding one bond (`etanol`, `ciclohexanol`:
  one structure; `propanol`: two; `bencenodiol`, `metilfenol`: three; `metanotetrol`: one placement); the fill variant
  that keeps prefix locants out keeps the suffix's out too (render.js omits both together: `etanol`,
  `triclorometanol`); a ring's closing bond is filled as `1(n)`, sorted 1 < 1(n) < 2. `placementReading()` maps
  `suffixAtoms` onto the named graph; every verdict has a `suffixAtoms` field.
- **Diagnosis:** halogen paths generalised to one-atom groups (`hidroxi`: never lengthens a chain, `X:O` shape,
  «sustituyentes»); a numbering dropped at N0 now gives null instead of an `undefined` NUMBERING message; MISSING_LOCANTS
  treats suffix slots like the prefixes' (no `bencenol` → «Faltan números»); LOCANT_ORDER covers the suffix's locants
  (`butano-4,1-diol`) and sorts `1(n)` between 1 and 2; `alcoholBeyondRules()` nulls the cases that need an alcohol
  message (below). Rules that hold for an alcohol keep working: BRANCH_AT_END, LONGER_CHAIN (a longer chain with as many
  OH groups), NUMBERING/RING_NUMBERING at N1–N4 after an N0 tie, ALPHABETICAL_ORDER, UNGROUPED, MULTIPLIER_KIND,
  NEEDLESS_LOCANTS (prefixes; `(1-hidroximetil)`), OLD_STYLE on a segment (`3-buten-2-ol`).
- **Dialog:** the new tiles with their colours; `1(n)` has a tooltip (its accessible name stays its text).

## Decisions

- **`fenol` is one whole-word tile** (kind `benzene`, value 'phenol'), not `fen` + `ol`: the engine's `fen` is no tile a
  student would look for, and a whole word keeps the template-like rules (no locants, its group at 1, counted by the
  letters). It sits in «Anillos» beside `benceno` because it is the name the app gives first (the traditional names of
  I-51a3 go to «Nombres tradicionales»). `benceno ol` still reads (`bencenol`, the phenol molecule → `otherName`).
- **`1(n)` is one tile that writes the ring's own size**, not a parenthesis control plus a number: the engine only ever
  cites the closing bond as 1(ring size), so a single tile cannot form a meaningless `2(5)` and needs no new error code.
  It is a locant of a ring's `eno`/`ino` only (TILE_ORDER elsewhere, also before the root in the old style); the plain
  number n still reads as the closing bond (`ciclohex-6-eno-1,2,4-triol` → `otherName`).
- **The suffix slot role is `carbon`** (domain 1…n, as a prefix's): §15.5.3 step 2's «principal-group lowest locants» is
  the engine's numbering, judged through `otherName`, not a narrower search domain.
- **`hidroxi` shares the halogen code paths** (`isAtomGroup()`), rather than a renamed node type, so no R-5a1 test or
  tree shape changes.
- **Deliberate, tested nulls** (diagnose.js header «Alcohols», for I-51a3): a chain or ring numbering dropped at N0
  (`butan-3-ol`, `ciclohexan-2-ol`, `benceno-1,5-diol`); a student suffix whose OH count differs from the engine's
  (`2-hidroxipropano`, `2-hidroxipropan-1-ol`, `(4-hidroxifenil)metano`, `4-hidroxitolueno`); a ring parent against a
  chain one in a molecule with OH groups (RING_IS_PARENT says «un anillo manda siempre», which OH groups overturn:
  `(2-hidroxietil)ciclohexano`, `(4-hidroxiciclohexil)metanol`); old-style suffix locants (`2-propanol`: OLD_STYLE says
  «delante de «eno» o «ino»»; the verdict's note gives `propan-2-ol`); needless suffix locants (`etan-1-ol`,
  `triclorometan-1-ol`); `bencenol`.
- Benzene with a suffix and a letter on a single prefix (`p-clorobencenol`) is POSITIONAL «different» (the engine names
  that molecule `fenol`-based); old-style numbers before `benceno` whose count does not match the suffix stay
  BENZENE_BONDS (`1,2,3-bencenodiol`).
- The parent's highlight after «Dibujar» includes the OH (the engine's parent parts, render.js `suffixGroupIds()`); the
  e2e counts distinct highlighted atoms.

## Deviations

- None from the brief's requirements. Beyond them: an alcohol tokenize property test, `isCycloName(name, closing)` so
  the ring closed loop of I-50a now reads its `1(n)` names (the ring diagnosis sweeps keep excluding them: their
  mutation helper rewrites plain numbers only), and the `1(n)` tooltip.
- Not changed (left to I-51a3 with the Ayuda line): the Ayuda sentence «Por ahora solo leo nombres de hidrocarburos …
  y de sus derivados halogenados» (`index.html` `#help-name-to-drawing`) does not mention alcohols yet.
