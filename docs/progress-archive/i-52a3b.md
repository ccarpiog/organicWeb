## What was built

- **Where the O-bound checks run:** `oBoundChecks()` right after `esterChecks()` (the principal –COO– group's own checks) and before
  the acid's, the alcohol's, the C=O checks and the parent choice, when `esterSideDiffers()` (computed once per name) finds the
  student's side none the engine writes in any style it offers. Before, that test made the whole diagnosis null.
- **Order inside:** ESTER_TRADITIONAL → each group's own name (BRANCH_RING_NUMBERING `oBound`, ESTER_ALKYL_CHAIN, then the
  branch-name checks on the branches inside the group) → ALPHABETICAL_ORDER `oBound` → UNGROUPED `oBound` → MULTIPLIER_KIND `oBound`
  → NEEDLESS_LOCANTS `oBound` → ESTER_ALKYL_NAME → BEYOND.
- **Groups compared on the molecule** (`oBoundGroups()`): each group's words (assembled from the student's tree without its
  multiplier) against the engine's words for the same atoms in every style offered, read from each style's naming parts
  (`oBoundWordOf()`); a group is the engine's when it matches one style.
- **ESTER_ALKYL_CHAIN** compares the student's chain with the engine's (`alkylChainCriteria()`, ACYL_CHAIN's twin with the free
  valence first): length, multiple bonds, double bonds, the carbon bonded to the oxygen, the bonds' and the prefixes' locants.
- **Two rings across an ester:** `nameSubstituent()` perceives one ring, so the engine's O-bound group (and any branch inside it) is
  named in the group's own ester, the group + bridge O + –COO– carbon + =O (`oBoundMolecule()`), as the engine does
  (naming/index.js withSplitEster()); without it `benzoato de 6-metilfenilo` overflowed the stack and got null.
- **ESTER_PREFIX_NAME** (first of BRANCH_NAME_CHECKS) for an ester prefix of another kind; **ACYL_NAME** for `etanoiloxi` /
  `metanoiloxi` (its word variant, `written` without `oxi`); `esterPrefixWords()`' BEYOND is gone but for the impossible reverse.
- **ESTER_CLASS_NAME** (`esterClassNameDiagnosis()`): a class name whose oxygen is the bridge oxygen of an engine suffix –COO–; any
  other class name beside an ester principal group now gets the class-name rules (CLASS_NAME_NONE; it was null).

## Decisions

- **Codes: the existing rule's where its message holds, new where it must differ** (I-52a3a's principle). Reused with an `oBound`
  variant of their message and the ester step: BRANCH_RING_NUMBERING, ALPHABETICAL_ORDER, UNGROUPED, MULTIPLIER_KIND,
  NEEDLESS_LOCANTS; ACYL_NAME as it is. New: ESTER_TRADITIONAL (no rule speaks of a traditional word's pairing), ESTER_ALKYL_CHAIN
  (no rule names an alkyl branch's own chain or numbering; acid-part branches stay null), ESTER_ALKYL_NAME (fallback),
  ESTER_PREFIX_NAME (ACYL_NAME's oxo variant says «una rama que se une por el carbono de un C=O», false for an acyloxy group),
  ESTER_CLASS_NAME (ESTER_GROUP's twin). Each kind of mistake has its own code and message.
- **Rule numbers** of the new codes are those of the rule each parallels (ESTER_CLASS_NAME 1 after ESTER_GROUP, ESTER_TRADITIONAL 2
  after SUBSTITUTED_TEMPLATE, ESTER_PREFIX_NAME 5 first of the branch names, ESTER_ALKYL_CHAIN / ESTER_ALKYL_NAME 5 after
  BRANCH_RING_NUMBERING), as the class names'; the reused codes keep theirs. They only place the codes in DIAGNOSES.
- **O-bound before the acid part's rules**: the explanation's ester step comes right after the group step, before the chain; the
  I-52a3a pin of `4-metilbutanoato de propan-1-ilo` expected the O-bound rules to speak. With the side right, the acid part's rule
  speaks (`4-metilbutanoato de propilo` → BRANCH_AT_END).
- **The traditional pairing rule**, from the engine: `carbonylAlternative()` renders `acetato de …` from the main (default-style)
  naming, so the traditional word goes with `isopropilo` only; the message says so plainly and quotes the systematic name with the
  student's group; step «Monta el nombre», which lists both.
- **Steps:** `ester` for one O-bound group, `diester` for two (each the other's fallback); `diesterStep()` says how two groups are
  written (alphabetical order with «y», `di` / `bis`).
- **Alphabetical order on the side** compares the words without the final `o` (as the engine cites the groups as branches:
  `metil` before `metilbutil`, where `metilo` would follow `metilbutilo`).
- **No render.js:** `reverse-tiles.test.js` forbids it in src/reverse (design §15.4); the engine's words come from its naming parts.
- **ESTER_PREFIX_NAME's «aquí «acetil»»** is quoted from the engine's parent-level prefix words; inside a compound branch the naming
  holds no deeper words, so the clause is left out.
- **Chemistry:** nothing from memory; every name and form is the forward engine's, every rule worded as explain.js words it.

  metilo».»

## Review resolutions

Codex adversarial review (`docs/reviews/I-52a3b.md`): ship-with-fixes, 3 should-fix, all fixed in `src/reverse/diagnose.js` with
regression cases in `reverse-diagnose-esters.test.js`.

- **Multiplier transplanted** (`propanodioato de bis(1,1-dimetiletilo)` → «di(1,1-dimetiletilo)», the `di` of `di-tert-butilo`):
  MULTIPLIER_KIND on the O-bound side now runs only on a group whose words the engine writes in an offered style (`ok`); otherwise
  the group's own mistake speaks (here ESTER_ALKYL_NAME, «tert-butilo»).
- **Explanation in another style** (`propanodioato de 1-metiletilo y 1-metiletilo` → «bis(1-metiletilo)» but a step prescribing
  `diisopropilo`): UNGROUPED, MULTIPLIER_KIND and ALPHABETICAL_ORDER on the O-bound side carry the style of the side they quote
  (`groupStyle()`, new `sideStyle()`); `diagnose()` reports it as the diagnosis's `style` with that naming's parent
  (`shownNaming()`), so diagnosisExplanation() opens the explanation that writes the side so (asserted for two substituted-style
  cases and a pin one).
- **Double-bond tie-break** (`etanoato de 3-etenilhex-1-in-3-ilo`, both six-carbon chains with one multiple bond): new
  ESTER_ALKYL_CHAIN reason `doubles`, «…y, entre las más largas, con los mismos enlaces múltiples, gana la que tiene más enlaces
  dobles. Se escribe «3-etinilhex-1-en-3-ilo», no «3-etenilhex-1-in-3-ilo».»; its words are MORE_DOUBLE_BONDS' own, now shared
  through `DIAGNOSIS_PHRASES.doubleBondTie` (that message unchanged, asserted).
