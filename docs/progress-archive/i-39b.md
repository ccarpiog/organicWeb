# I-39b — Acyl prefixes `formil-` / `acetil-` / `-oil` (split from I-39)

- Risk: high · worker: opus · reviewer: Codex ship-with-fixes, 1 should-fix fixed (`docs/reviews/I-39b.md`).
- Split: I-39 (v2 §3.19) became I-39a `ciano-`, I-39b acyl prefixes, I-39c ester/amide
  prefixes + pair matrix (design §13.4).

## Decisions

- **Where X belongs (recorded in design §13.6).** An aldehyde or ketone carbon X does *not*
  join `outsideCarbons()` (unlike the I-39a `ciano-` carbon). X stays an ordinary skeleton
  carbon, because IUPAC 2013 keeps it in the chain whenever the chain rules allow:
  `ácido 4-oxopentanoico` (never `ácido 3-acetilpropanoico`), `ácido 3-metil-4-oxobutanoico`
  on a length tie (more prefixes, P-45.2.1). Only when the parent (or a branch chain) misses X
  is X the attachment atom of an **acyl branch whose own chain starts at X** (locant 1; X has
  at most one other carbon, so it is always a chain end). So the parent choice is unchanged
  and X counts in no parent length; the acceptance wording "parent choice ignores X" holds in
  that sense only (X is never *excluded* from the candidate chains).
- **Structure.** `buildSubstituent()` flags such a branch `acyl` and keeps the C=O of X as an
  `oxo` prefix at locant 1 (so formula counts, π counts and highlights need no change);
  `render.js citedPrefixes()` leaves that occurrence out of the name, `acylEndingTokens()`
  writes the ending.
- **Prefix words (from memory, IUPAC 2013 P-65.1.7).** `formil` for X alone (a –CHO off the
  chain; P-66.6.1.2); `acetil` for an unsubstituted CH₃–CO– (retained preferred prefix,
  P-65.1.7.2.1), used instead of `etanoil`; a substituted two-carbon acyl is systematic,
  `(2-cloroetanoil)`, matching the app's `ácido 2-cloroetanoico` (no `cloroacetil`); otherwise
  the acid's name with `-oico` → `-oil` (`propanoil`, `butanoil`, `(2-metilpropanoil)`,
  `(but-2-enoil)`, `(but-2-inoil)`, `(3-oxobutanoil)`). English `formyl`, `acetyl`, `-oyl`.
  Unenclosed without own prefixes/locants, `di`/`bis` as usual, alphabetised by the complete
  prefix (`acetil` under a, `2-metilpropanoil` under m).
- **`manyAldehydes` (from memory).** Kept for three or more –CHO on one carbon piece with the
  aldehyde principal: IUPAC 2013 cites every principal group as a suffix when it can
  (`propano-1,2,3-tricarbaldehído`, like citric acid's `propano-1,2,3-tricarboxílico`), so
  `4-formilheptanodial` is not the IUPAC name. Narrowed: below an acid, ester, amide or
  nitrile, or on another carbon piece, extra –CHO groups are named (`oxo-` / `formil-`). The
  message now says why `formil-` is not used.
- **`acylSubstituent`.** Kept only for –CO–C≡N (a one-carbon acyl carrying a `ciano`; IUPAC
  `carbonocianidoil`, from memory), found by `unnamedAcyl()` on every emitted style; new
  message.
- **Rings.** Acyl groups with a ring keep `sideChainCarbonyl` / `ringAldehyde` (I-40).
  Seniority unchanged.

## Review fix

- Codex should-fix (`docs/reviews/I-39b.md`): when an acyl branch's own chain was chosen, the
  C=O oxygen of X was counted as an `oxo` prefix in the comparison data (P4/N3/N4/N5), so
  `OC(=O)C(C(=O)C(C(=O)C)C(Cl)C)CCCCCC` became `…2-[2-(1-cloroetil)-3-oxobutanoil]…`.
  Fixed in `buildSubstituent()`: `prefixesOf` leaves that oxygen out (it stays in the
  structure for counts and highlights; the parent-level numbering never saw it). Now
  `ácido 2-(2-acetil-3-clorobutanoil)octanoico` in every style; regression in
  `tests/unit/acyl.test.js` (both lexicons) and `names.tsv`.
