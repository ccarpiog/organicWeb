## What was built

- `src/reverse/diagnose.js` (new, pure, bundler-safe): `diagnose({tree, spec}, verdict, readings?,
  namer?)` → `null` or a JSON-safe `{code, rule, traceRule, message, step, style, student, parent,
  focus, tiles}`. Rules in R-3 order, first match wins; 16 codes: `BRANCH_AT_END`, `LONGER_CHAIN`,
  `MORE_MULTIPLE_BONDS`, `MORE_DOUBLE_BONDS`, `MORE_SUBSTITUENTS`, `CHAIN_LOCANTS`,
  `CHAIN_ALPHABETICAL`, `NUMBERING`, `ALPHABETICAL_ORDER`, `UNGROUPED`, `MULTIPLIER_KIND`,
  `LOCANT_ORDER`, `NEEDLESS_LOCANTS`, `MISSING_LOCANTS`, `SEGMENT_ORDER`, `OLD_STYLE`.
- Chain-choice rules (1–4) follow the student's chain through the naming engine's own trace, so
  they agree with it by construction; `src/naming/` unchanged (only its public `nameMolecule` with
  `prefixStyle` is called).
- The student's prefix style (`isopropil` / `pin` / `substituted`) is recognised from the
  branches' **structure** (each written branch, at any depth, compared with how the engine names
  that branch in each offered style, ignoring locants, multipliers and `an`; ties keep the default
  style), and the diagnosis compares against the engine's naming in that style.
- Branch identity: structural key plus the attachment bond order, at every nesting depth
  (`ownPrefixAtoms()`, a new export of `src/reverse/build.js`).
- `step` is an `explain()` step id (`chain`, `tiebreak`, `numbering`, `substituents`, `order`,
  `assemble`). **I-49b must use `diagnosisExplanation(verdict, explain, namer?)` →
  `{naming, steps, index}`** (the explanation of the naming in the diagnosis's style), not
  `explain(verdict.naming)`; `diagnosisNaming()` gives that naming; `diagnosisStepIndex(steps,
  diagnosis)` resolves the index with fallbacks (e.g. no `order` step with a single prefix group →
  `substituents`).
- `readName()` (`src/reverse/index.js`) attaches `diagnosis` to `otherName` verdicts only.
- Spanish drafts (pending teacher review) in `DIAGNOSIS_TEXTS` / `DIAGNOSIS_PHRASES`; `DIAGNOSES`
  holds example data per code for R-7's wording list.

## Decisions and deviations

- With left-out locants every placement of the drawn structure (up to 16) is a reading; the
  kindest diagnosis is kept (`butineno` → `MISSING_LOCANTS`, not `NUMBERING`), so
  `diagnosis.student` may differ from `verdict.studentParent`.
- Rules that cannot occur as `otherName` (documented in the module header, behaviour tested): a
  wrong multiplier count is already `invalid`; needless parent-level prefix locants are always
  preceded by rule 1; `MISSING_LOCANTS` alone gives a `missingLocants` verdict; `NUMBERING` at the
  alphabetical-name rule (N5) never happens.
- `null` diagnosis: a branch written in a style the engine does not offer for that molecule
  (`4-(1,1-dimetiletil)heptano`), or a branch whose own chain or numbering is wrong
  (`5-(butan-3-il)nonano`).
- `OLD_STYLE` overlaps the existing old-style note: I-49b decides whether to show both.
- The verdict's `message` is unchanged; I-49b inserts the diagnosis message between its two
  sentences.
- Existing tests touched: the exact-keys verdict-shape test (`reverse-read.test.js`) and the purity
  test's file list / import whitelist (`reverse-tiles.test.js`).

## Review fixes (Codex should-fix ×3)

1. Exact prefix-style matching misdiagnosed `4-metil-6-(1-metiletan-1-il)nonano` as `NUMBERING` →
   style recognised by structure; now `NEEDLESS_LOCANTS` («…se escribe «6-(1-metiletil)», no
   «6-(1-metiletan-1-il)».»).
2. Nested identity: `5-[2-metil-2-(metan-1-il)propil]nonano` gave `ALPHABETICAL_ORDER` → rooted
   structural identity with bond order; both citation orders now `UNGROUPED`
   («…«5-(2,2-dimetilpropil)»…»); `7-(3-metiliden-2-metilbutil)tridecano` stays
   `ALPHABETICAL_ORDER` (bond order distinguishes `metiliden`).
3. Step context: `6-metil-4-(propan-2-il)nonano` (`NUMBERING`, pin style) linked to the
   default-style explanation, which endorsed the student's numbering → `diagnosisExplanation()`;
   the test checks the opened numbering step numbers the parent the app's way.
