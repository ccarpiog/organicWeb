## Acceptance

  blocks, cyclic components and attachment points, and classifies a structure as acyclic,
  single carbocycle, heterocycle, fused, bridged, spiro or several rings — met

- `canonicalKey()` in `src/model/graph.js`: the unchanged tree key for trees, a monocycle key

  met. The tree encoder no longer recurses and throws on a cycle.
- SMILES reads/writes ring closures (`1`–`9`, `%nn`, bond symbols on either end; `1` ≡
  `%01`); unclosed, self, duplicate and conflicting closures rejected; acyclic output
  unchanged — met.
- No crash or loop on rings in editor, validate, naming, explain, Ordenar dibujo, 90° view,
  autosave restore, oracle — met (unit + `tests/e2e/rings.spec.js`).
- `npm test` 0 (473 pass), `npm run check` 0 (80 files), `npm run e2e` 0 (153 pass),

## Decisions

- Error codes: `CYCLE` is kept for a single carbocycle ("Aún no sé nombrar anillos, pero
  pronto aprenderé…"); new `RING_SYSTEM` with `ringKind` (heterociclo, fusionados, con puente,
  espiro, varios anillos), one Spanish message each; both carry the ring atoms and count as
  `isNotNameableYet()`.
- Rings are checked before `TOO_BIG` and `HETEROATOM`, so an O in a ring gets the
  heterocycle message.
- Mixed polycycles: every polycyclic block is evaluated; any bridged block → `bridged`,
  else `fused`; then `spiro`, then `several`. Fused vs bridged is exact for two rings and
  approximate beyond (cubane counts as fused) — it only selects an out-of-scope message.
- 90° view falls back with "Hay anillos: se ve el dibujo normal."; `rightangle.js` returns
  `CYCLE`; `canonical.js` (Ordenar dibujo) refuses rings instead of looping.
- Oracle keeps rings and compares by structure after checking ring counts; molecules with
  two or more rings have no structural key yet and fail. Generator stays acyclic.
