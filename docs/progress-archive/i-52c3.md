## What was built

- **Templates:** «Nombres tradicionales» gains `anilina` and `bencilamina` after `ftalonitrilo` (texts the lexicon's
  TRADITIONAL_NAMES). Each places the amine's nitrogen at its carbon 1 as `fenol` places its OH (SUFFIX_GROUPS `amine`), so
  interpret.js reads it as the placed suffix (kind 'amine'), amineSlots() gives the prefixes' `N` slots exactly as for an `amina`
  suffix, build.js attachSuffix() makes it the amine nitrogen (`N` groups bonded to it, VALENCE on a third), and the search counts
  its bonds at index N_VALUE (`metilanilina`: `N`, 2, 3 or 4, four structures, `ambiguous`). `bencilamina` is a chain template of
  one carbon with its phenyl, as `acetofenona` holds its C=O and phenyl on carbon 1.
- **Letters on `anilina`:** a group written `N` stands on the nitrogen and occupies no ring position, so the engine's lettered
  forms read (`N-etil-p-metilanilina`, `p-bromo-N,N-dimetilanilina`); the tokenizer reads a letter after a complete prefix (POS in
  AFTER_PREFIX). An `N` and a letter on one prefix are POSITIONAL with their own message; a group without numbers beside a letter
  still counts on the ring (three positions), and the message then adds «Si un grupo va unido al nitrógeno, escribe «N» delante
  (N-etil-p-metilanilina).». A letter on `bencenamina` gets its own message pointing at the numbers or at `anilina`.
- **Class names:** the `amina` tile right after a complete name-level prefix (no parent read yet) is the class word
  (startsAmineClass(), makeClassParent()): the parent a `classWord` node as for `éter`, the prefixes before it the groups on the
  nitrogen. checkAmineClassName() refuses a locant, `N` or letter on a group, a one-atom, alkoxy, `ciano`, `carboxi` or `amino`
  group, an acyl group (an amide) and a doubly bonded branch (TILE_ORDER, each with its hint); a fourth group is the builder's
  VALENCE on the nitrogen. The assembler writes the name in one word (rule 13: no spaces, rule 5's hyphen before `tert-` after a
  multiplier, each group enclosed only as a prefix by itself); the tokenizer reads the `amina` after a complete group as class
  AMCLASS. The interpreter makes the nitrogen the parent (kind 'amine', one atom, implicit slots), the builder creates it
  (amineClassNitrogen(), three bonds), the search models it as a one-atom chain of valence three.
- **Verdicts:** the exact comparison with the engine's alternatives makes the engine's forms `alternative`; every other class
  name or template name that builds is `otherName` (or `outOfScope` when the engine refuses: two rings, `N-fenilanilina`,
  `difenilamina`).
- **Diagnosis:** an amine's class name is a deliberate null before every rule (diagnose(), isAmineClassName()), so the ether's
  class-name rules never read it. On the templates the shared rules run (`anilina` admits every prefix the engine names;
  `bencilamina` none: SUBSTITUTED_TEMPLATE), and amineChecks() (first, R-6c1) gives the templates' own mistakes their «Amines»
  null categories. wordsOf() now drops a prefix's letter, so `N-metil-p-etilanilina` reads «etil» before «metil» (before R-6c3 a
  lettered prefix never stood beside another valid one).
- **Dialog / Ayuda:** tooltips for both templates, the `amina` tooltip says it also ends a class name; the Ayuda intro ends
  «…, y de sus nitrilos y aminas.» and a new «Aminas» paragraph explains `amina`, `N`, `amino`, `anilina`, `bencilamina` and the
  class names.

## Decisions

- **One `amina` tile, two places (the class word has no tile of its own).** The engine writes the same word `amina` in
  `etanamina` and `metilamina`; the student picks `amina` either way and the parser decides by its place: after a parent's ending
  (or its locants or multiplier) the suffix, right after a complete group with no parent the class word. A second `amina` tile
  (kind `classWord`, as `éter`) would put two identical tiles in «Grupos» for the student to tell apart, and break the
  catalogue's one-text-one-tile rule (`reverse-tiles.test.js`: texts unique). No parent can end in `il`, so the two places never
  meet; `amina` alone stays the stray suffix with its old hint.
- **The class name is one word, as the engine writes it,** also `butiltert-butilamina` with no hyphen between the groups
  (naming/index.js amineClassName() joins them with ''); followed, not fixed (open question below). A group with prefixes of its
  own is enclosed as a prefix by itself (`(2-cloroetil)metilamina`), the app's convention for names the engine never writes.
- **`bencilamina` is in.** The engine writes it (style `traditional`, for the bare fenilmetanamina) and I-52c1 counted it with the
  class names held for this phase; it reads as a template, not as `bencil` + `amina` (no `bencil` tile). `alcohol bencílico`, the
  alcohols' twin, stays unread (see Open questions).
- **No `N,p-`:** the letter and `N` on one prefix are POSITIONAL (reused code, own message); the LOCANT_COUNT the multiplier would
  add there is skipped, so the student reads the one message that says what to write (`N,4-dimetilanilina`).
- **The class name's count by the builder:** one to three groups; a fourth is VALENCE on the nitrogen (no new parse code, the
  R-6c1 message «El nitrógeno de la amina tendría 4 enlaces…»).
- **`correct` does not announce the class name** (index.js TRADITIONAL_STYLES: `traditional` only), like the ether's
  functional-class name: `bencenamina` says «También se llama «anilina»», `metanamina` says only «¡Correcto!». Not changed (open
  question below).
- **Chemistry:** nothing from memory; every name, form, label and refusal is the forward engine's.

## Deviations / open questions

- **SUBSTITUTED_TEMPLATE on `anilina` never applies:** the brief asks for it on «a prefix the engine does not write on
  `anilina`», but the engine writes `anilina` with every prefix it names (aromatic.js: any monoamine of benzene, ring and N
  prefixes). The prefixes it does not write there are another principal group (`seniority`), a second amine group (`count`) or
  another prefix style (`style`), all «Amines» nulls; SUBSTITUTED_TEMPLATE speaks on `bencilamina`, which the engine writes bare.
- **Open question (forward engine, not changed): `butiltert-butilamina`.** amineClassName() joins the groups without a hyphen
  before `tert-`; since `tert-butil` sorts by «butil», only `butil` can stand before it (`butiltert-butilamina`; with `etil`,
  `isopropil`… it goes first: `tert-butiletilamina`). Followed by the reverse engine. Usage (from memory) would separate the
  groups (`butil(tert-butil)amina`); a fix belongs to `src/naming/index.js`.
- **Open question: announce the class name on `correct`?** `metanamina` → «¡Correcto!» only, as for an ether's class name; the
  amineClass label calls it «nombre tradicional…», so a teacher may want «También se llama «metilamina»» (index.js
  TRADITIONAL_STYLES).
- **`alcohol bencílico`** (the engine's alternative of `fenilmetanol`) stays unread; no planned phase covers it (a two-word name
  with the class word «alcohol»).
- `etil-p-metilanilina` (a group without `N` beside a letter) is POSITIONAL, counting the group on the ring, with the `N` hint,
  rather than searched on the nitrogen.
- design.md §15.8's Status column is not updated (the user's uncommitted file).
