## What was done

- `validate.js`: a benzene whose other substituents are carbon branches, halogens or alkoxy groups
  is admitted as a `(…fenil)`/`(…fenoxi)` prefix when exactly one branch carries functional groups
  and the molecule has no ester; own messages for substituted benzoyl and esters with a substituted
  benzene; CYCLE message reworded. Safety net: if the engine still picks the ring as parent, refuse.
- `substituent.js` / `render.js` / `index.js` / `principal.js` / lexicons: phenyl numbered from the
  attachment carbon (lowest locants, then alphabetical order, Kekulé-neutral), enclosed in
  parentheses, alphabetised under its first letter; retained `acetofenona` / `alcohol bencílico` /
  `bencilamina` never offered for a substituted phenyl.
- `explain.js`: the substituents step describes the phenyl's own numbering and prefixes.
- Oracle: new `generateSubstitutedPhenyls()` (500 molecules per run); README updated.
- Docs: design §14.5, CLAUDE.md scope, README, Ayuda out-of-scope line.
- Existing tests updated where formerly refused molecules are now named (e.g.
  `(2,3,4,5,6-pentametilfenil)metanol`); oracle test counts 79→81 skipped, 2261→2311 passed.

## Decisions (from memory)

- Systematic name first, as for unsubstituted phenyl: `ácido 2-(3-metilfenil)etanoico` with
  `…acético` under Otras formas; `N-(4-metilfenil)etanamida` with `…acetamida`; aldehyde, amide and
  nitrile on carbon 2 follow the same pattern.
- Scope narrower than allowed: OH or other junior groups on the phenyl stay refused
  (e.g. `ácido 2-(4-hidroxifenil)etanoico`).
- Scramble test leaves out the chain-numbering step, whose A/B options may swap order with atom ids
  (pre-existing behaviour of chain explanations).
