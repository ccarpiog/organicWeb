## What was built

- **The amide's own checks** (amideChecks(), right after amineChecks() in firstRule(), now only when the engine's principal group
  is an amide; each rule 1, step `group`, «Reconoce el grupo funcional», which says the C=O and the nitrogen are one group, how
  the amide is written and, beside other groups, the seniority):
  - **AMIDE_GROUP** (new, ESTER_GROUP's twin, amideSplit()) — an amide group of the engine's suffix whose carbon no amide suffix,
    `carbamoil` or acylamino prefix of the student's has (studentAmideCarbons()), when that carbon is the student's parent's or a
    parent-level prefix's own: the C=O and the nitrogen written apart (`1-aminobutanal`, `1-amino-1-oxobutano`,
    `1-(metilamino)butanal` → «N-metilbutanamida», `4-amino-4-oxobutanamida` → «butanodiamida», `(aminooxometil)benceno` →
    «benzamida»); the groups on its nitrogen go before the name with `N` (`nitrogenGroups()`).
  - **CARBONYL_SENIORITY** (extended) — a junior suffix beside the amide (`2-carbamoilbutanonitrilo` → «2-cianobutanamida»,
    `4-carbamoilbutan-2-ona`, `3-carbamoilpropanal`, `2-(acetilamino)etan-1-ol`, `4-carbamoilfenol`, `4-carbamoilbenzaldehído`),
    and, through acidChecks() / esterChecks() (amideChecks() no longer answers there), a student's amide suffix beside an acid's
    –COOH or an ester's –COO–, the junior `amide` (amideJunior()): written `oxo` and `amino` with the same number when its carbon is
    the parent's chain's (`4-carboxibutanamida` → «ácido 5-amino-5-oxopentanoico», `3-(metoxicarbonil)propanamida`) or the O-bound
    group's (`2-(acetiloxi)etanamida` → «…va en el nombre del grupo unido al otro oxígeno, con dos prefijos…»), else with the
    engine's amide prefix (`4-carboxibenzamida` → «carbamoil», `N-(carboximetil)etanamida` → «acetilamino»).
  - **KETONE_NOT_ALDEHYDE** (reused) — `1-carbamoilbutanal` → «2-oxopentanamida».
  - **AMIDE_CARBON** (new, NITRILE_CARBON's twin through groupCarbon()) — `carboxamida` after a chain, or the amide's carbon as the

## Decisions

- **Codes: the shared ones where the message holds, four twins where a family-named code exists** (the acid's, ester's and
  nitrile's precedent: ACID_CARBON → ESTER_CARBON → NITRILE_CARBON are twins through one function; ESTER_GROUP, ESTER_IN_CHAIN,
  ESTER_PREFIX_NAME are named after the ester). AMIDE_GROUP, AMIDE_CARBON, AMIDE_IN_CHAIN and AMIDE_PREFIX_NAME reuse their twins'
  functions or structure (groupCarbon(), groupCarbonText(), branchAtEnd(), the branch-name check loop); no near-duplicate logic.
- **amideChecks() only for an amide principal.** I-52d1 put a student's amide suffix beside an acid or an ester in amideChecks()
  so that their seniority code would not put the amide's nitrogen apart; CARBONYL_SENIORITY now has the amide's words (`junior`,
  `chainAmide`, amideJunior()), so the acid's and the ester's checks run first as for every other junior group — ACID_GROUP and
  ESTER_GROUP keep their place before it (a –COOH split beside a student's `amida` is still ACID_GROUP).
- **AMIDE_GROUP only on the student's parent or a parent-level prefix's own carbon.** `oxo` and `amino` on a carbon of a compound
  branch's chain is how the engine writes a junior amide there too: beside it the student's mistake is the parent choice, which the
  rules name truly (`N-(2-amino-2-oxoetil)etanamida` → MORE_SUBSTITUENTS «…(1; la tuya tiene 0)», the engine's P4: a group on the
  amide's nitrogen counts for no chain; `3-(2-amino-2-oxoetil)pentano` → MORE_CARBONYL_GROUPS).
- **The other amide groups of I-52d1's `parent` category go to the parent rules**, not a code of their own (no AMIDE_SIDE): the
  trace's own rule speaks and is true. A side-of-the-nitrogen message as AMINE_SIDE's would need the amide's nitrogen reasoning in
  etherSide(); left for a teacher's view (Deviations).
- **Seniority: the whole order** (`amideSeniority`, equal to naming/seniority.js SENIORITY in Spanish words) whenever the amide is
  the principal group or the student's junior suffix, as the brief, the nitrile's and the amine's messages; the amide's group step
  gives it beside a `ciano`, the acid's and the ester's steps a shorter order (Deviations).
- **«grupo amida»** in every message (the explanation's SUFFIX_GROUP_WORDS.amide, generic for –CONH₂, –CONH–, –CON–); the
  principal «la amida (un C=O unido a un nitrógeno)» (R-6c4a's).
- **An acylamino prefix written for the principal amide is CARBONYL_PREFIX** (the amide written as a prefix), its holder sentence
  saying where the student's chain goes, as the ester's acyloxy case (`oBound`) does; the nitrogen-groups sentence is not added
  then (the student's chain is that group).
- **AMIDE_PREFIX_NAME `inChain` also for an `oxo` + `amino` branch whose carbon the chain takes in** (`[(aminooxometil)metil]`):
  the same reason (the amide's carbon counts for the branch's chain), so one message: «…la amida no forma una rama aparte,
  «X», sino que se nombra con dos prefijos…». An `oxo` + `amino` branch on an O-bound group's own chain keeps ESTER_ALKYL_CHAIN
  (its «longer» message is true and its right form the engine's).
- **Test categories refined:** `amideCategory()` and `amidePrefixCategory()` read `carbon` only when the student's amide carbons
  are the engine's (groupCarbon()'s condition, as I-52b3's nitrileCategory()); `2-(4-carbamoilciclohexil)etanamida` is `parent`,
  CARBONYL_PARENT. No sweep count changed.
- **Chemistry:** nothing from memory; every name, form and order is the forward engine's; the amide sentences follow the
  explanation's own (amideGroupStep(), chainAmideNote(), carbamoylDescription()).

## Review fix (Codex adversarial review, `docs/reviews/I-52d4.md`)

- **Finding (should-fix):** «Do not interpret a missing RINGCHAIN trace as zero chain amides» (`src/reverse/diagnose.js`
  principalParent()). `2-(benzoilamino)etanamida` gave CARBONYL_PARENT «…Aquí el anillo lleva uno y las cadenas no llevan
  ninguno, así que gana el anillo: «N-(2-amino-2-oxoetil)benzamida».» — false: the student's ethanamide chain carries an amide.
- **Cause:** principalParent() took the counts from the `RINGCHAIN` trace step and, without one, assumed every principal group on
  the ring (`chain` 0). That holds for rings.js nameRingWithStyle(), which writes the step whenever a side chain carries groups
  of its own, but the benzene pipeline (naming/aromatic.js) never writes it, even on a tie. Removing the I-52d1 `AMIDE_NULLS`
  guard in this phase exposed it: a benzamide whose nitrogen carries a chain with an amide group (ring 1, chain 1, the ring on
  the tie) is the first in-scope tie on benzene. The engine's answer is right; the student's mistake is the parent choice.
- **Fix:** new ringChainCounts() (diagnose.js, beside principalParent()): the `RINGCHAIN` step's values when present; else, on
  a one-ring molecule whose parent is the ring, the engine's own comparison (parent.js ringOrChain() on the engine's ring, the
  call naming/index.js makes), read as nameRingWithStyle() reads it (the chains count when some group lies off the ring);
  otherwise the earlier counts (every group on the ring, none on a chain: true there). New import `ringOrChain` (parent.js,
  already allowed) and `cyclomaticNumber` (graph.js, already allowed); no rings.js import (the reverse import allowlist,

  «N-(2-amino-2-oxoetil)benzamida».» — the cyclohexane twin's message (`2-[(ciclohexanocarbonil)amino]etanamida`, whose trace
  has the step).
- **Families:** principalParent() serves all of them (alcohol HYDROXY_PARENT; aldehyde/ketone, acid, ester, nitrile, amine,
